# Design Directions

## A. Alice 控制台 — 选定

**视觉主张**：208px 分组侧栏 + 紧凑顶栏 + 单层内容表面。暖中性深色基底，Alice 青只标记激活、焦点与真实连接；中文系统字体与 monospace 技术信息分工。品牌符号为几何“数据花结 A”。

**交互主张**：环境/API 状态始终可见；导航按“工作台 / 数据 / 系统 / 支持”分组。列表优先扫读，窄窗收起次要列。加载、空态与错误都直接说明影响和恢复路径。

**适配原因**：最适合长期高频桌面操作，能同时承载 Studio 业务和官方 OpenBB 系统工具，不会把底层能力藏起来。

**风险**：如果图标含义不够准确，折叠侧栏会降低首次可发现性；需要 tooltip 与 740px 实机 QA。

## B. 数据账本

**视觉主张**：顶部紧凑导航，主体强调密集表格与 ledger 式行分隔，品牌极弱，使用偏冷的灰蓝中性色。

**交互主张**：通过命令面板和全局搜索跨越数据源、模型、路由和环境；适合键盘重度用户。

**适配原因**：数据目录和查询效率高，视觉克制。

**风险**：九项导航拥挤问题在中等窗口仍存在；系统管理流程对新用户更难理解；Alice 品牌信号过弱。

## C. Alice 导航台

**视觉主张**：首页使用较大的连接拓扑和引导步骤，其他页面采用两级顶部导航；品牌青与曲线连接图形更明显。

**交互主张**：通过可视化路径解释“环境 → 服务 → 数据源 → 查询”。

**适配原因**：首次上手更友好，Alice 品牌记忆强。

**风险**：容易滑向营销 hero 和装饰性仪表盘；可视化会占用有限桌面高度，重复使用效率较低。

## Decision

选择 **A. Alice 控制台**。它是三个方向中最安静、最易扫读且最能保留官方功能的方案。采用 C 的“连接路径”只作为首页的一条紧凑工作流，不做大型装饰图；采用 B 的表格密度，但不用命令面板作为唯一入口。

## Anti-template Review

- 避免：蓝紫渐变、发光 orb、玻璃卡片、营销 hero、四张同质指标卡、每个元素都做圆角胶囊。
- 保留：侧栏、表格、状态条等常见操作台模式；理由是它们匹配路由数量、扫读和桌面最小宽度，不是装饰模板。
- 产品特征：Alice 数据花结 A、实时运行环境/API 状态、业务/系统双层信息架构和准确 OpenBB attribution。
