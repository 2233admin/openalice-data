# 中国市场开放数据平台：产品范围

## 决策摘要

本项目采用 OpenBB 的模块化数据平台模型，建设一个中国市场优先、中文可部署、同时兼容美国市场接口的全市场项目。A 股、数字货币和国内期货是首批市场域；港股及其他市场按实际需求以 Provider 扩展。项目不定位为单独的 A 股 Provider，也不把任何单一行情源视为完整市场。

## 决策卡

- Driver：项目负责人
- Approver：项目负责人
- Contributors：数据平台、量化研究与部署维护人员
- Outcome：统一后续仓库结构、接口兼容、本地化和市场接入方向
- 阶段：已确认产品方向，具体数据源与交付优先级继续迭代

## 目标

1. 提供中文优先的安装、配置、文档、接口描述、错误信息和运维体验。
2. 以统一的数据模型接入中国股票、数字货币、国内期货等市场。
3. 保留 OpenBB 原有美国市场数据接口，尽量维持上游兼容。
4. 允许港股等市场根据项目需求新增 Provider，不把地区判断写死在核心中。
5. 支持 Python SDK、REST API 和容器化中文部署，并可作为其他研究或交易系统的隔离数据服务。
6. 所有结果携带数据源、市场时间和接收时间；多源结果显式报告覆盖度、缺口和新鲜度。

## 市场范围与优先级

| 优先级 | 市场域 | 首期范围 | 兼容策略 |
|---|---|---|---|
| P0 | 中国股票 | A 股基础资料、行情、历史数据和交易日历 | 新建中国股票 Provider；数据源可替换、可仲裁 |
| P0 | 数字货币 | 现货与衍生品行情、K 线、交易所元数据 | 复用 OpenBB 标准模型，补充中国用户常用交易所与中文展示 |
| P0 | 国内期货 | 合约、主力/连续合约、行情、交易日历和基础资料 | 新建国内期货 Provider；明确交易所与夜盘语义 |
| 保留 | 美国市场 | 上游已有接口和 Provider 能力 | 尽量原样保留；通过上游同步机制更新 |
| 按需 | 港股及其他市场 | 由具体研究与业务需求确定 | 以插件扩展，不进入核心硬编码 |

## 中文本地化

“支持中文部署”不只等于翻译 README。首期至少包含：

- `zh-CN` 默认语言选项和可切换的英文回退；
- 中文安装、配置、升级、备份和故障排查文档；
- API 文档中的中文标题、字段解释和示例；
- 可本地配置的时区、交易日历、代理、镜像和数据源凭证；
- Docker/Compose 部署入口及中文健康检查说明；
- 日志和错误码保持稳定机器标识，面向用户的信息提供中文文本。

## 架构边界

```text
Python SDK / REST API / MCP / 中文管理界面
                    |
       统一标准模型与查询接口
                    |
  市场域：股票 | 数字货币 | 国内期货 | 美股 | 港股…
                    |
 Provider：QMT | AKShare | 交易所 | OpenBB 原 Provider…
                    |
      覆盖校验、来源仲裁、缓存与遥测
```

- OpenBB Core：尽量保持上游兼容，只修改真正属于平台通用能力的部分。
- 市场域：定义证券标识、交易日历、字段语义和查询模型。
- Provider：封装第三方 SDK/API、授权、限流与故障，不向上泄漏源特有结构。
- 仲裁层：使用同一个 universe 衡量覆盖，输出 `complete`、缺失标的、来源和时间戳。
- 部署层：独立进程或容器运行，可与现有系统解耦升级和降级。

## 需求与验收标准

### P0：平台身份与中文部署

- 根文档明确中国市场优先定位，并保留 OpenBB 归属和许可证。
- 在全新中文 Windows/Linux 环境中，可依照中文文档启动 API。
- API 文档至少支持中文说明，错误响应保留稳定错误码。

### P0：市场插件契约

- 股票、数字货币和期货分别拥有独立市场模块，不混用证券代码或交易日历规则。
- 标准结果必须包含 `source`、`vendor_time` 和 `received_at`。
- 全市场请求必须返回目标数量、有效数量、缺失列表和 `complete`；HTTP 成功不等于数据完整。

### P0：美国市场兼容

- 保留所纳入上游快照中的美国市场接口和 Provider 注册机制。
- 自有接口变更不得无说明地破坏上游调用形式。
- 定期从只读 `upstream` 获取安全修复和兼容更新。

### P1：港股与其他市场

- 新市场通过 Provider 和市场域注册接入。
- 接入不要求修改其他市场的标识、日历或数据源实现。

## 非目标

- 不把项目收窄为 A 股行情工具。
- 不承诺所有数据源免费、无授权或永久可用。
- 不把研究数据平台直接等同于自动实盘交易系统。
- 不为追求表面兼容而掩盖中国市场特有的交易日历、夜盘、复权和合约规则。
- 首期不一次性实现 OpenBB 上游全部界面的完整中文翻译。

## 方案选择与权衡

| 方案 | 上游兼容 | 中国市场适配 | 维护成本 | 结论 |
|---|---:|---:|---:|---|
| 只写 A 股 Provider | 高 | 低，覆盖单一资产 | 低 | 范围不足，否决 |
| 深度改写 OpenBB Core | 低 | 高 | 很高，上游同步困难 | 不作为默认路径 |
| 保持 Core、扩展市场域和 Provider | 高 | 高 | 中 | 采用 |
| 从零自研全平台 | 无 | 可定制 | 极高 | 已有轮子重复建设，否决 |
